# Handoff notes

Context for anyone (or any session) picking this up. See README for build and test commands.

| `picker.js` | Subdivision picker (groups, list, map clicks) |
| `overlay.js` | 2D canvas drawing for objects, names, legend, editing handles, the outline of the subdivisions under the pointer; reused by PNG and SVG export |
| `paint.js` | Country fills, recolour and remove a colour (countries and subdivisions), legend colour order and counts |
| `schemes.js` | Color schemes (pure, unit tested): ColorBrewer class colors for sequential and diverging scales (lightest sequential class dropped, it is near white on land), Viridis and Cividis, paint swatch sets (Default, Okabe–Ito, Set 2, Dark 2, Paired, Tableau 10) with ColorBrewer's color-blind and print ratings; symmetric diverging breaks; Machado et al. (2009) color-vision matrices, CIEDE2000, and `clashes` (pairs at least 10 apart normally but under 10 with a deficiency) |
| `patterns.js` | Pattern fills: a paint is a hex color or `p:<type>:<background>:<ink>` (diagonal, wide diagonal, horizontal, vertical, crosshatch, dots, checkers, fine dots), so fills, units, labels, legend order and saved maps stay plain strings. Each pattern is a square tile in CSS pixels; the globe draws the same shapes in the fill shader (`gl.js` FS_FILL `mask`, numbered in `PATTERN_TYPES` order, from a second palette texture holding ink and type; on the globe the pattern is laid out from an anchor on the Earth, the centre of the country's largest part, projected each frame (a third texture holds the anchors, `setAnchors`; units use their country's), so it moves with the country while the globe is dragged and keeps its size in CSS pixels when zooming. It is also turned so its "up" is north at the anchor as drawn on the screen (`vNor`): a country that tilts as it moves away from the centre of the globe takes its pattern with it, instead of the pattern staying upright and seeming to spin about the anchor. It is not squashed with the land near the horizon. Near the horizon the anchor of a very large country can be on the far side, where it moves the other way; the pattern there is foreshortened anyway), the overlay and PNG legend use a canvas tile, SVG export a `<pattern>` (`svgctx.registerDef`). Tiny markers and the clash check use the background color |

| `statsrc.js` | Reads `scripts/sources/stat-*.json` for the editor and builds `statCredit(app.stat)`, the credit printed on exports (source note and SVG `<desc>`) |
| `ui-stats.js` | Data panel's Statistic menu, Year menu and "Fetch again"; fetches from api.worldbank.org when an indicator is chosen, colors the map through `colourRows` in `ui-paint.js` (shared with your own data), marks countries without data, paints the US states for electoral votes |
| `seats.js` | Seat counter (pure, unit tested): `ELECTIONS`, the election maps (US Electoral College on Natural Earth's states, 538 and 270; US House on `us-cd119`, 435 and 218, DC's delegate not counted; UK Commons on `gb-wpc-2024`, 650 and 326; Dáil on `ie-dail-2023`, 174 and 88, seats per constituency from the source), `tally` (seats per paint in legend order, seats not called, a winner with a majority), `arrange` (first colour from the left, second from the right, not called in the middle) |
| `seatbar.js` | The seat counter on the map, drawn like the legend when an election map has painted units: title, majority, leading totals, the bar with the majority line, each colour with its legend name and seats, notes (Maine and Nebraska counted whole, a warning if the units do not add up). | `units.js` | Paintable subdivisions: a country's layers (`layersOf`, `activeLayer`, `setLayer`), per-country-and-layer loading when the pointer rests (`LOAD_DELAY`), triangulation into the globe's subdivision mesh, the unit or group under a point at the chosen detail, painting by unit code (Natural Earth `adm1_code`, or `layer:code`) |
| `history.js` | Undo and redo (snapshots of country fills, painted subdivisions and objects) |
| `persist.js` | `getState`/`setState` (validated), map codes `GM1.`, downloads, autosave |
| `fonts.js` | Label fonts; web fonts load only when chosen |
| `input.js` | Pointer, wheel, keyboard, hover tag |
| `ui-*.js` | Panels: paint (palette, search, lists, data), style, legend, objects, file |
| `export.js` | PNG export; SVG export (vector layers in named groups, one path per country with `data-name` and the shown lakes cut out, metadata in `<desc>`); source note text |
| `projections.js` | Export projections and fitting: globe as shown or square, whole-world flat maps centred on the globe's meridian, regional maps fitted to points sampled from the visible globe (conic standard parallels at 1/6 and 5/6 of the latitude span) |
| `ui-modes.js` | Panel modes (Paint, Data, Draw, Style, Legend, Export): rail on desktop, bottom tabs and a resizable sheet on phones; keys 1–6; remembers the last mode; selecting an object switches to Draw. `window.ecumene.mode(m)` for tests |
| `svgctx.js` | Canvas-2D-compatible recorder that writes SVG, so overlay drawing and d3 `geoPath` are shared by screen and SVG output |

Outside `src/js/`: `src/groups.js` (country groups and name matching) and `src/overseas.js` (the overseas parts split from France and the Netherlands), both CommonJS so the build scripts and tests can require them.

Conventions: modules share state only through `app`; UI panels re-render on events rather than being called directly; anything pure goes in a module without DOM access so it can be unit tested.

## Rendering design
- Ocean and shading: fullscreen triangle (`uMode` 0 ocean and background, 1 limb shading and rim).
- Country fills: triangle mesh (earcut, 4-degree grid clipping, antimeridian unwrap, Antarctica closed through the pole) with a per-vertex country id and a palette texture. Hover and painting change palette entries.
- Painted subdivisions: each country's admin-1 units load when the pointer rests on it for 75 ms (or on a click, for touch), are triangulated in the browser with the same code as the build (`scripts/lib/tri.js`, about 40-140 ms per country) and appended to a second fill mesh with its own 8192-entry palette. That pass draws after the countries and before the lines, skipping unpainted units, so the country's colour shows through them and the borders stay on top. An earlier version drew units on the 2D overlay; with Russia, Canada, the US and China painted it took 50-330 ms a frame, the GL pass costs nothing measurable. Painted units are `app.units` (`'Country|adm1_code'` -> colour) and save as `u: [{c, k: {country: [codes]}, l}]`. Painting a whole country (Subdivisions off, lists, groups, search) clears its units. Detail `r`/`g` paints every unit of the same region or constituent part, where the country's index offers that grouping.
- Lines (borders, graticule, lakes, rivers, hover outline): instanced quads with back-hemisphere clipping in the vertex shader.
- Regions and annotations: the 2D overlay canvas with d3's spherical clipping, so edges follow great circles.
- Picking: exact point-in-polygon on unwrapped polygons, not a raster.
- Enclaves merged by alias: Baikonur to Kazakhstan, USNB Guantanamo Bay to Cuba.
- Overseas parts split out (`src/overseas.js`): French Guiana, Guadeloupe, Martinique, Mayotte and Réunion from France, the Caribbean Netherlands (Bonaire, Saba, Sint Eustatius) from the Netherlands, as Natural Earth's map units do. Polygons are moved by lon/lat box into new geometries appended after the 255 world-atlas ones, so existing ids do not move. `build_tris.js` and `build.js` (which writes `countries.json`) both use the split topology. Continents place them geographically; the EU and Eurozone groups include the French regions (EU territory, euro), NATO does not (outside the treaty area). Maps saved with data `ne10m` (before the split) paint each part like its parent on load (`persist.js`); maps now save `d: 'ne10m-2'`. The boxes are hand-set; on 14 Oct 2026 `node scripts/check_overseas.js` compared the split with Natural Earth's admin-0 map units (public domain), which publish these parts on their own: every part has exactly the units' polygons and none is left in France or the Netherlands. A unit test (`tests/unit/groups.test.js`) keeps the units' polygon centres as a fixture, so a changed box that catches the wrong island fails without the network.
- Country ids are 16-bit in `tris.bin` and the palette texture has 1024 entries (`PAL_N` in `gl.js`), so more units fit; there are 259 names now.
- Small-country markers: any country under about 40,000 km² (`TINY_MAX` in `data.js`) gets a dot while it is under 5 px across on screen (`TINY_PX` in `view.js`), clickable within 7 px. Drawn on the overlay below regions, filled with the country's paint, and written to SVG as `<circle data-name>` in a `small-countries` group. Uninhabited reefs and banks, the sovereign base areas and the Cyprus buffer zone are left out (`NO_MARKER`). The Vatican has zero area in the 10m data (quantisation collapses it), so its marker shows at every zoom. Layer toggle `layers.tiny`.

## Data
- Site layout: `dist/index.html` is the home page (`src/home/`), `dist/app/` the editor with `data/` and `admin1/` beside it. The editor reads `?new`, `?start=wikipedia|data|flat` and `?example=<name>` (loads `../examples/<name>.json`, whose `x` field sets export options and `mode` the panel mode); without them it continues the autosaved map. Starting fresh only overwrites the autosave once something changes. The home page loads no third-party resources (fonts self-hosted) and its globe uses world-atlas 110m.
- Example gallery (#7): `site/examples/gallery.json` lists every example (title, caption, how it was made, source, alt text, `featured`). The build (`scripts/lib/gallery.js`) puts the four featured cards on the home page (markers `<!-- examples -->` and `<!-- gallery-link -->` in `src/home/index.html`) and writes `dist/gallery/index.html` from `src/gallery/index.html` with the home page's styles and every card. A caption can say when its data was read, `{fetched}`, `{year}` or `{read}`, filled from the saved map; the build stops if the map has no such date. `scripts/make_examples.js [name]` makes each example's map and thumbnail with the built editor (`GPU=1` for the graphics card; the statistics and NATO examples read live data, so they need the network). Twelve examples: the EU, GDP per capita, the fictional Byzantium, the UK's countries (featured); electoral votes, life expectancy, under-5 mortality in Viridis (statistics); NATO members by when they joined (join years read from nato.int's member table, pasted as categories; non-members left unpainted, not No data); the euro area within the EU (patterns); continents by UN M49; the counties of Texas (colored so neighbours differ, since painted subdivisions have no lines between them); Ireland's four provinces. Tests check every listed example has its files, captions are filled, only Byzantium is fictional, and each opens in the editor without errors, credits its data in the SVG and loads nothing from other sites.
- The source line on exports wraps onto more lines (at its " · " separators, then at spaces) when it is too long for the frame, keeping to the space beside a legend at the bottom; before, a long line ran off the edge. `tests/e2e/helpers.js` `sourceNote(svg)` reads it back as one text.
- Countries: Natural Earth 10m via `world-atlas`, served as `app/data/countries.json`.
- `tris.bin` and `phys.bin`: deflate-raw, 1e-5 degree quantised, delta-coded (formats in `decode.js`). `phys.bin` stores the always-water lakes first, then the 29 major lakes (scalerank 0–1), so each set can be drawn alone; header numbers 9–12 give both prefixes, number 13 the count of lake polygons, and a list at the end gives each polygon's ring count (its shore, then its islands), so lakes can be rebuilt as polygons. The decoder still reads files without the always-water prefix or the list.
- Lakes lying wholly inside another lake are dropped at build time (`CONTAINED` in `scripts/build_phys.js`, checked against what the build finds): Natural Earth stores Georgian Bay, North Channel, Saginaw Bay and Whitefish Bay over Lakes Huron and Superior, four small lakes twice, and two small ones inside Lake Chany and Reindeer Lake. Overlaps showed as land in the SVG's even-odd lake fill and drew extra shores across the water.
- Always-water lakes (`SEA` in `scripts/build_phys.js`, now just the IJsselmeer with the Markermeer, the former Zuiderzee): the countries layer fills them as land and Natural Earth ranks the IJsselmeer 2, below major. They are filled at every Lakes setting, their shore is drawn with the borders like coast, clicks there count as sea (`inSea` in `data.js`, for countries and subdivisions), and the SVG has them in an `inland-sea` group.
- Lakes in SVG export: every lake lies inside a country polygon in the countries layer (and inside subdivisions). Export cuts the lakes the map shows (always-water, plus major or all by the Lakes setting) out of each country path and painted subdivision (`scripts/lib/cut.js`, cached per setting), so the shapes stop at the shore; borders still come from the original topology. The clipper (`polygon-clipping`) is a separate `app/clip.js`, loaded on the first export. Cutting is planar in lon/lat: pieces get continuous longitudes (rings round a pole are closed through it), everything is snapped to 1e-5° (unsnapped, Brazil fails), long edges get points along their great circle first, and points the clipper drops along straight lon/lat runs (Sudan's 22°N border) are put back. A piece that cannot be cut is kept whole and named in `<desc>`; `tests/unit/cut.test.mjs` cuts every country and subdivision file at every setting so that does not happen. A whole-world map at Lakes = All cuts in about 1.5 s on a desktop. Globe PNGs are unaffected (they come from the GL render, where lakes are drawn over the land).
- Subdivisions: Natural Earth 10m admin-1, one TopoJSON per country in `admin1/`, fetched on demand. Each unit has `id` (its position in Natural Earth's list for that country, which exact outlines save) and `c` (`adm1_code`, unique, which painted units save). Units of the overseas parts move out of France and the Netherlands into their own entries (the Caribbean Netherlands gets Bonaire, Saba and Sint Eustatius; the French regions are single units and paint whole); the parent's other units keep their ids, so ids can have gaps. Where no unit covers part of a country (the north of Åland's main island, Argentina's side of the Southern Patagonian Ice Field, small areas of India, China, Palestine, Croatia, the US, the Philippines, Bhutan and Antarctica), the build adds one more unit, "Rest of <country>" with code `<file>+0` (for example `ALD+0`): the country minus its units with `polygon-clipping` (also used by SVG export, see above), dropping slivers under 10 km² or under 1 km wide. Countries across 180° get continuous longitudes first, and a piece the clipper cannot handle is redone in 1° tiles, quartered down to 1/8° (only one 1/8° tile of Chilean fjord is skipped). The Baikonur and Guantánamo Bay units belong to Kazakhstan and Cuba, listed after their own units so ids do not move.
- Exact outlines (`t:'shape'`) are saved by reference (`{k:'c',names}` or `{k:'a1',c,ids}`), never by coordinates, and rebuilt with `topojson.merge`.
- Fictional scenario: `app.fictional`, saved as `fi: true` (absent otherwise), set only by the Byzantium example (there is no control for it; an earlier checkbox was removed at Ari's request). When on, and while the map still has drawn regions, routes or markers (`isFictional` in `export.js`), the SVG description starts with "Fictional scenario: the regions, routes and events drawn on this map are invented and are not historical borders or events. The country borders and coastlines underneath are Natural Earth's present-day ones." and the source line printed on the image says "Fictional scenario" (the source line can be switched off in Export; the SVG description cannot). The SVG `<title>` is the legend title, so the Byzantium example's already reads "(fictional)". Only the "A restored Byzantium, 1453" example sets it; its regions are freehand polygons and its arrows and dates are invented (the home-page caption says so). The flag is not cleared by editing, so someone who turns the example into a different map by changing its regions keeps the label until they delete every drawn object or start from another map; opening any other map or example replaces the flag.
- Country groups (`src/groups.js`): the lists were typed by hand and on 14 Oct 2026 `node --max-http-header-size=1000000 scripts/check_groups.js` compared them with pages that name the members, and every one agreed. EU (27) and Eurozone (21): the EU's EU countries page, plus the ECB's euro page for the euro area. NATO (32): nato.int's member table. UN Security Council permanent members: Article 23 of the Charter (names the Republic of China and the USSR, whose seats China and Russia hold). G7 and G20: the Government of Canada's pages (the EU takes part in the G7 and is a G20 member, neither as a country; the African Union is a G20 member). ASEAN (11, with Timor-Leste): the Government of Japan's Ministry of Foreign Affairs page, because asean.org answers a script with a JavaScript challenge. Wikidata (CC0) agrees for EU, NATO, G7 and G20; it is not used for the Eurozone (it does not model euro area membership) or ASEAN (its statements list Australia and some people). The overseas parts that go with France in the EU and the euro (French Guiana, Guadeloupe, Martinique, Mayotte, Réunion) are on top of the counts and are not on the source pages. Each group's panel note says where it was checked and when (`GROUP_SOURCES`, `GROUPS_CHECKED`); update both when you re-run the script. One open point: g20.org, the 2026 US presidency's own site, lists "State Participants" without South Africa and with Poland (the African Union and EU as "Non-State Participants"); the map keeps the 19 standing members, as the Government of Canada's page and the Council of the EU list them, and the G20 note says so. The terms of each page are in the README sources table: only the EU's content is under an open licence (CC BY 4.0); the others are facts read for checking, with no licence claimed. In `scripts/sources/groups.json` the `licence` is what we hold (the facts, "no licence claimed") and the optional `terms` is the terms of the pages checked, shown in the README as "terms of the pages checked"; `tests/unit/layers.test.mjs` still rejects any non-commercial text in `licence`, so a data layer can never slip in under a restricted licence, and the UN and Canada page terms (non-commercial only) live in `terms`.
- Continents follow the UN Statistics Division's M49 classification (Ari's decision, 14 Oct 2026: broad diplomatic and geographic consensus over intuition). M49 has one Americas region; its sub-regions split it here (South America is its South America intermediate region; Northern America, Central America and the Caribbean are North America). `scripts/check_groups.js` compares every map place that has an ISO code with M49 (247 agree). Changes made to match it: Cyprus to Asia (Western Asia in M49, though an EU member), with Northern Cyprus, the buffer zone, Akrotiri and Dhekelia, which M49 does not list but which share the island; South Georgia to South America, Heard and McDonald Islands to Oceania, the French Southern and Antarctic Lands to Africa, so Antarctica is the continent alone. Places M49 does not list keep the continent of the land around them: Kosovo, Taiwan, Somaliland, Siachen Glacier, the Spratly Is., Scarborough Reef, Bajo Nuevo and Serranilla Banks, Clipperton, the Coral Sea Is. and the Indian Ocean Territories. Natural Earth's own `CONTINENT` field was also compared: it leaves many island territories as "Seven seas (open ocean)" with no continent, so it is not used. The UN page's terms allow personal use only; the classification is used as a fact and nothing is copied from the page.
- Statistics (#13): the Data panel's Statistic menu. World Bank indicators (World Development Indicators, CC BY 4.0, 12 listed in `scripts/sources/stat-worldbank.json`, each with its own code, title and who collected it; all are CC BY 4.0 in the World Bank's series metadata) are fetched live from `api.worldbank.org` in the browser when one is chosen, one request for the last 15 years. The editor makes requests to other sites only on a person's choice: this one, and reading a Google Sheets link (see Your own data); the panel says so. Nothing is bundled and the build needs no update. The map saves what it used, `st: {k:'wb', c: code, y: year or 'latest', t: date fetched, v: {ISO3: value}, ys?: {ISO3: year}}` (values rounded to 7 significant digits), so reopening or sharing a map code never changes its numbers and never touches the network; "Fetch again" is the only refresh. Year menu: the default is the latest year where at least 90% of the best year's countries have a value; "Most recent for each country" uses each country's latest value and the legend title and credit say "most recent available, 2021–2024". Matching uses ISO alpha-3 codes: `src/iso.js` (generated by `scripts/build_iso.js` from Natural Earth's admin-0 table and committed) maps each code to the map country's id, which is its ISO numeric code, plus the overseas parts split from France and the Netherlands; Kosovo (World Bank code XKX) is matched by name; Ashmore and Cartier Is. shares Australia's numeric id and takes no code. A country without a value is painted `NO_DATA_PAINT` (grey with fine dots) with a "No data" legend entry unless "Mark countries with no data" is off (saved as `ds.nd`). The World Bank's figure for France includes its overseas departments, so French Guiana and the others show no data while France's value still counts them; Taiwan, Western Sahara and some others have no World Bank data. A statistic colors the whole map: what was painted before goes (one undo step; undo restores the statistic and legend title). Pasting rows, or Clear all colors, drops the statistic and its credit. Exports credit it ("World Bank, World Development Indicators, NY.GDP.PCAP.CD, 2023, CC BY 4.0", plus the date fetched and the collecting organisation in the SVG `<desc>`). US electoral votes are bundled in `stats.js` (House seats from the 2020 Census apportionment plus two senators, DC 3; valid for the 2024 and 2028 presidential elections; the 2030 census sets the electors from 2032) and paint Natural Earth's US units; Maine and Nebraska's district votes are not shown. Democracy indices are left out for licence reasons (V-Dem is CC BY-SA, the EIU Democracy Index and Freedom House are not openly licensed). The browser tests answer the World Bank from a fixture so CI needs no network; the live API was checked by hand on 14 Oct 2026. The home page's GDP example is made with this feature: `scripts/make_examples.js gdp` fetches the 2022 series live, and the example file keeps the values with the fetch date (14 Oct 2026); it replaced a hand-kept CSV that no longer matched the World Bank's current series. The electoral-vote seat table was first typed from memory; on 14 Oct 2026 `node scripts/check_electoral.js` compared all 50 states with the Census Bureau's apportionment Table 1 (SHA-256 recorded in `stat-us-electoral.json`) and every number matched, and a unit test pins the table's fingerprint (run the script and update the fingerprint if it ever changes). The rule (seats plus two, DC 3, 538 in all) is confirmed by usa.gov; the National Archives page could not be reached from the checking machine, so the per-state electoral counts have no second per-state source. An earlier draft said the table held for 2032 too; that was wrong (the 2030 census applies from 2032).
- Your own data (#14): paste a table (from a spreadsheet, with or without a header), open a .csv, .tsv, .txt or .xlsx file, or load a Google Sheets link. Sheets links are turned into the sheet's CSV address, keeping the tab (`export?format=csv&gid=` for a sheet shared as "anyone with the link", `pub?output=csv` for one published to the web); Google allows the export to be read from the browser (checked 14 Oct 2026 with a public sheet; the published-to-web form was not tested against a real sheet). A sheet that is not shared answers with a sign-in page, which is reported as such. The preview guesses the column of places (most cells recognised: names, aliases, ISO alpha-3 or alpha-2 codes; `src/iso.js` now has `ISO2_3`), the column of values (the rightmost mostly-numeric one, so the latest year in a table of years) and the header row; all three can be changed, and places not recognised are listed with "did you mean". The values decide the coloring: numbers become classes with the scale settings, #hex colors are used as they are, words become categories in the paint set's colors (no more categories than the set has colors). Coloring replaces the map's colors in one undo step, like a statistic, and marks countries without a value as No data unless that is switched off; the heading of the value column becomes the legend title unless one was typed. The rows used (only the two columns), where they came from and when, and the Source field are saved with the map as `im` (`table.js` `importRecord`, checked by `validImport`), so reopening or sharing a map never reads the file or sheet again; Load the sheet again to refresh. Exports credit it: the Source as given, marked "Not checked by Ecumene", or, with no source, "supplied by the map's author, not checked by Ecumene". Up to 5,000 rows and 10 MB files. Countries only: matching states, counties or other subdivisions by name or code is a possible follow-up. The paste box replaced the old two-column reader (`Ecu.parseData` is kept for its tests); pasted rows now also mark the remaining countries as No data, so the old "colour by data" test sees six legend entries. Undo now also restores the legend labels when it goes back past a coloring by data.

- Other subdivision layers (#37): each comes from an entry in `scripts/sources/` (publisher, edition, licence, exact credit, download URL and SHA-256, which fields hold code, name and groupings). `scripts/fetch_sources.js` downloads the raw file from the mirror release `data-sources` (checksum-named assets, never replaced; `--origin` fetches from the publisher, records the new checksum and stages the file in `data/src/mirror/` for `gh release upload data-sources`). `scripts/build_layers.js` fits every unit to the Natural Earth country outline (units wholly inside are kept as published; others are cut back to the coast, dropping pieces under 0.5 km²), orients polygons for d3 by area (ArcGIS winds the other way), and writes `data/layers/<id>/<file>.json` plus `data/layers/index.json` (per country: id, menu name, unit word, edition, file, count, groupings, credit). The editor reads the index at start; a country with several layers shows "Layer for <country>" in the paint panel and in the outline picker. Codes of a layer's units carry its id (`gb-wpc-2024:E14001063`), so saved maps (`u`) need no new field and Natural Earth codes are unchanged; exact outlines save the layer as `ref.y`. A country is painted with one layer at a time: its layer is that of its paint, else the one chosen; switching clears the other layer's paint after asking, as one undo step. Exports credit each layer used (title, edition, URL, credit in `<desc>`; the short credit on the source note). The README sources table is generated from `scripts/sources` (`node scripts/fetch_sources.js --readme`) and a test checks it. A source can have several `parts` (the UK county layers join Great Britain from OS Boundary-Line and Northern Ireland from OSNI); a part's download can `extract` one Shapefile layer from a zip archive (OS ships Boundary-Line as one 737 MB archive: `--origin` keeps it in `data/src/cache/`, converts the layer with mapshaper and stores gzipped GeoJSON, so the mirror holds 18 MB). Fields can merge pieces by name (`dissolve`: OS splits Carnarvonshire into 8, Tailte Éireann a constituency into dozens), tidy names (`case: "title"` for names in capitals, `strip` a regex such as " Council$" or a seat count), keep a seat count as the unit's `s` (`seats`: a regex whose first group is the number, read from the name field before `strip`; the Dáil layer has it, 174 seats in 43 constituencies, and the build prints the total), use `"@slug"` codes for name-only data, and take groupings from a field, from the code's first letter, or from the Natural Earth admin-1 unit under the unit's centre (`"from": "ne-admin1"`). `simplify` passes mapshaper options (150 m for full-detail sources). The build stops if a unit loses its shape, and where one unit lies inside another in the source (Tailte Éireann's generalised Cork County covers Cork City) it cuts the smaller out of the larger and says so; any other overlap stops it. Layers (#10): UK Westminster constituencies 2024 (650), counties and unitary authorities December 2025 (218, ONS), ceremonial counties (97: England, Wales's preserved counties, Scotland's lieutenancy areas, Northern Ireland's six counties since its county boroughs are not in the open data), historic counties (94, 1888/1889 plus Northern Ireland's six); Ireland counties (26), local authority areas (31) and Dáil constituencies 2023 (43), all Tailte Éireann. Each file is 114-374 KB and covers 98.8-99.4% of its country on the map. Postcode areas are left out: no current open boundaries exist (see #10). A part can also `filter` features (`{field, in}` or `{field, notIn}`: the Census county file has the territories, which are their own countries on the map) and `lookup` field values (state FIPS codes to names), and a name can be a template of fields (`"{STATEFP} {CD119FP}"`) with `replace` rules ("Alaska 00" becomes "Alaska (at-large)"). US layers (#11, U.S. Census Bureau 2024 cartographic boundaries 1:5M, public domain): counties and equivalents of the 50 states and DC (3,144, grouped by state, 1,974 KB, so its source sets `maxKB` 2000), congressional districts of the 119th Congress (436 with DC's delegate), and Puerto Rico's 78 municipios (Natural Earth has none). Layer files are quantised to about 1e-4° whatever their extent (a fixed 1e5 steps across the US, nearly 360° wide because of the Aleutians, moved Alaska's fjord coasts off the land). In headless tests the US counties take 5-7 s to show because SwiftShader renders each frame slowly; on a real GPU they are ready in about 220 ms with 5 ms frames.

## Adding a data layer
1. Check the licence allows any use with credit (OGL, CC BY, public domain); note the exact credit wording the publisher asks for.
2. Add `scripts/sources/<id>.json` (copy `gb-wpc-2024.json`, or `gb-historic.json` for several parts, an archive and name-only data): id with the edition in it (a new edition is a new layer, so saved maps keep meaning what they meant), menu name, unit word, country as named on the map, publisher, URL, edition, licence and credit, the download URL (GeoJSON in WGS84; ArcGIS services take `outSR=4326&f=geojson`) and the code, name and grouping fields.
3. `node scripts/fetch_sources.js --origin <id>`, then upload the staged file: `gh release upload data-sources data/src/mirror/<file>`.
4. `node scripts/build_layers.js <id>`: check the unit count, size (under 1.5 MB per file) and coverage it prints.
5. `node scripts/fetch_sources.js --readme`, then `npm run test:unit` (the layer test checks credit, codes, fit and coverage) and look at it in the editor.
6. An election layer (one seat per unit, or a seat count per unit) can feed the seat counter: add it to `ELECTIONS` in `src/js/seats.js` with its total and majority, and to the totals in `tests/unit/seats.test.mjs`, which checks that the units add up.

## Known limits
- Natural Earth 10m: Jutland's northern tip appears attached; admin-1 is coarse for some countries and its UK "region" grouping mixes NUTS regions.
- Admin-0 countries keep some overseas parts inside the parent. French Guiana, Guadeloupe, Martinique, Mayotte, Réunion and the Caribbean Netherlands are split out (see Data); Svalbard (Norway), the Canaries (Spain), and the Azores and Madeira (Portugal) still paint with their parent. Exact outlines saved before the split that included French overseas departments lose those parts, since they are no longer in `FRA.json`.
- Subdivisions and countries come from different Natural Earth layers and mostly line up to the pixel. Where a whole area is missing from the subdivisions it becomes a "Rest of" unit (see Data); with borders turned off, hairlines can show along some coasts at high zoom.
- Browser tests are slow on SwiftShader (software rendering): 14-20 minutes for the whole suite on one CI machine in Oct 2026, against about 1.5 minutes on a desktop GPU. CI and headless Linux without a display use it; other machines use the real GPU (see `playwright.config.js`). CI therefore splits the browser tests across four machines (`--shard`, one test at a time rather than one file, so every test must open its own page and not rely on another test having run) with the unit tests on a fifth. It runs once per pull request and on main, not on pushes to branches without a pull request, and a newer push to a pull request cancels the run it replaces.
- Untested on real phones and touch screens.
